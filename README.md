# MirageItemUpgrade

Плагин улучшения предметов для **Paper 1.21.4+** (Java 22). Игрок кладёт предмет в особое меню `/upgrade`, платит монетками и ферментами улучшения и с некоторым шансом получает предмет уровнем выше. Рецепты улучшений создаются прямо в игре через встроенный GUI-редактор.

## Возможности

- Меню улучшений `/upgrade` с предпросмотром результата, стоимости и итогового шанса.
- Оплата монетками через **Vault** (работает с Essentials и любой другой экономикой, зарегистрированной в Vault).
- Второй вид оплаты — **ферменты улучшения**, предмет, который списывается из инвентаря.
- До **5 дополнительных одинаковых предметов** повышают шанс успеха.
- Игровой **GUI-редактор рецептов**: создание, правка, удаление, листание страниц.
- Рецепты сохраняются в `recipes.yml` асинхронно, без лагов основного потока.
- Строгое или мягкое сравнение предметов (с учётом мета-данных или только по материалу).
- Все тексты в `lang.yml` на **MiniMessage** (градиенты, hover, click), мягкая поддержка **PlaceholderAPI**.
- Современные API: Paper Brigadier-команды, Adventure, PersistentDataContainer, виртуальные потоки для ввода-вывода.
- Настраиваемые слоты меню, шаги редактора, значения рецептов по умолчанию и звуки.
- Безопасное меню: предметы возвращаются при закрытии, закрытие при выключении сервера, защита от shift-клика, двойного клика и перетаскивания в служебные слоты.

## Установка

1. Скопируйте `MirageItemUpgrade-v0.1.jar` в папку `plugins`.
2. Убедитесь, что установлены Vault и плагин экономики (Essentials или другой).
3. Запустите сервер. Будут созданы `config.yml`, `lang.yml`, а при первом сохранении рецепта и `recipes.yml`.
4. Настройте `config.yml` и `lang.yml` по желанию, выполните `/upgrade reload`.
5. Создайте первый рецепт командой `/upgrade admin`.

## Как это работает для игрока

1. Игрок вводит `/upgrade`.
2. Кладёт улучшаемый предмет в центральный слот. Если для предмета есть рецепт, справа появляется результат, а в информационном слоте цена и шанс.
3. По желанию кладёт в нижний ряд до 5 таких же предметов. Каждый повышает шанс успеха.
4. Нажимает кнопку **«Улучшить»**.
5. Плагин проверяет рецепт, слоты, монетки и ферменты, списывает оплату и бросает шанс.
   - **Успех:** игрок получает результат в инвентарь (если места нет, предмет падает на землю), основной предмет расходуется.
   - **Неудача:** основной предмет теряется, если у рецепта включена потеря, иначе остаётся в слоте. Дополнительные предметы сгорают в любом случае.
6. При закрытии меню все предметы из слотов возвращаются в инвентарь.

Если в основном слоте лежит стак из нескольких предметов, за одну попытку расходуется один предмет, остальные остаются в слоте.

В дополнительных слотах допускаются только предметы, одинаковые с основным (сравнение без учёта количества и прочности). Иначе попытка отклоняется.

## Команды и права

| Команда | Описание | Право |
|---|---|---|
| `/upgrade` | Открыть меню улучшений | `mirageitemupgrade.use` |
| `/upgrade admin` | Открыть редактор рецептов | `mirageitemupgrade.admin` |
| `/upgrade reload` | Перезагрузить `config.yml`, `lang.yml` и рецепты | `mirageitemupgrade.admin` |
| `/upgrade enzymes <игрок> <кол-во>` | Выдать ферменты улучшения (поддерживает селекторы `@a`, `@p`, ...) | `mirageitemupgrade.admin` |

Дополнительный алиас команды: `/itemupgrade`.

| Право | По умолчанию | Описание |
|---|---|---|
| `mirageitemupgrade.use` | все игроки | Доступ к меню улучшений |
| `mirageitemupgrade.admin` | операторы | Редактор, перезагрузка, выдача ферментов |

Команды зарегистрированы через Paper Brigadier API: подсказки аргументов и проверка прав работают на уровне дерева команд, недоступные подкоманды скрыты.

Пока рецепты загружаются при старте или после `reload`, меню и редактор отвечают сообщением «Рецепты ещё загружаются».

## Редактор рецептов

Открывается командой `/upgrade admin`.

### Список рецептов

- Каждый рецепт отображается значком исходного предмета с описанием: ID, результат, цена, ферменты, шанс, бонус, потеря при неудаче, строгое сравнение.
- **ЛКМ** по рецепту открывает редактор.
- **Shift + ПКМ** удаляет рецепт.
- Нижний ряд: предыдущая и следующая страницы, закрытие, кнопка **«Создать рецепт»**. На странице помещается 45 рецептов.

### Редактор одного рецепта

| Элемент | Действие |
|---|---|
| Слот «Исходный предмет» | Возьмите предмет курсором и нажмите на слот. Пустой курсор очищает слот. Предмет при этом не расходуется. Также работает Shift + клик по предмету в своём инвентаре |
| Слот «Результат» | То же самое. Количество результата равно размеру стака, который вы положили |
| Цена в монетках | ЛКМ прибавляет шаг, ПКМ отнимает, Shift умножает шаг |
| Цена в ферментах | Аналогично |
| Базовый шанс успеха | Аналогично, в процентах, от 0 до 100 |
| Бонус за доп. предмет | Аналогично, в процентах, от 0 до 100 |
| Потеря предмета при неудаче | Клик переключает «Да» и «Нет» |
| Строгое сравнение | Клик переключает «Да» и «Нет» |
| **Сохранить рецепт** | Нужны исходный предмет и результат |
| **Назад к списку** | Несохранённые изменения теряются |
| **Удалить рецепт** | Только для существующих рецептов |

Шаги изменения значений и значения нового рецепта задаются в `config.yml`. Закрытие редактора клавишей Esc отбрасывает несохранённые изменения.

### Строгое сравнение

- **Включено:** предмет должен совпасть с шаблоном полностью (название, лор, зачарования, прочие мета-данные). Количество и текущая прочность игнорируются.
- **Выключено:** сравнивается только материал.

Если подходят сразу несколько рецептов, сначала проверяются строгие, затем мягкие, в порядке ID.

### Цепочки улучшений

Результат одного рецепта можно сделать исходным предметом следующего. Для этого оставьте строгое сравнение включённым и положите в качестве исходного предмета ровно тот предмет, который выдаёт предыдущий рецепт.

## Ферменты улучшения

Ферменты — обычный предмет (материал задаётся в конфиге) с меткой в PersistentDataContainer, поэтому подделать его переименованием нельзя. Название и лор берутся из `lang.yml`.

- Выдача: `/upgrade enzymes <игрок> <кол-во>`.
- При попытке улучшения плагин считает ферменты в основном инвентаре игрока (хотбар и сумка), броню и вторую руку не учитывает.
- Списание происходит до броска шанса, оплата не возвращается при неудаче.
- Если после списания ферментов не удалось списать монетки, ферменты возвращаются автоматически.

## Расчёт шанса

```
шанс = min(100, базовый_шанс + число_доп_предметов × бонус_за_предмет)
```

Пример: базовый шанс 50%, бонус 10%, в доп. слотах 3 предмета. Итоговый шанс равен 80%.

Бросок выполняется один раз на попытку.

Порядок обработки попытки:

1. Проверка основного предмета и рецепта.
2. Проверка дополнительных слотов.
3. Проверка наличия монеток и ферментов.
4. Списание ферментов, затем монеток (при сбое монеток ферменты возвращаются).
5. Бросок шанса.
6. Расход дополнительных предметов.
7. Расход основного предмета (при успехе всегда, при неудаче по настройке рецепта) и выдача результата.

## Конфигурация

Файл `config.yml` содержит комментарии ко всем параметрам.

```yaml
menu:
  item-slot: 20
  result-slot: 24
  info-slot: 22
  confirm-slot: 49
  close-slot: 53
  extra-slots: [38, 39, 40, 41, 42]
  filler: BLACK_STAINED_GLASS_PANE

enzymes:
  material: PRISMARINE_SHARD
  glow: true

editor:
  coin-step: 100
  enzyme-step: 1
  chance-step: 1
  bonus-step: 1
  shift-multiplier: 10

recipe-defaults:
  coins: 1000
  enzymes: 5
  chance: 50
  bonus-per-extra: 10
  lose-on-fail: true
  strict: true

sounds:
  success: { sound: entity.player.levelup, volume: 1.0, pitch: 1.0 }
  failure: { sound: entity.item.break, volume: 1.0, pitch: 0.8 }
  error:   { sound: entity.villager.no, volume: 1.0, pitch: 1.0 }
  click:   { sound: ui.button.click, volume: 0.7, pitch: 1.2 }
```

### Раскладка меню

Меню имеет размер 54 слота (6 рядов), слоты нумеруются с 0. Требования:

- все слоты уникальны и находятся в диапазоне 0-53;
- дополнительных слотов не больше 5.

Если раскладка некорректна, в консоль выводится предупреждение и используется раскладка по умолчанию.

### Прочие параметры

- `enzymes.material` — любой предметный материал. При ошибке используется `PRISMARINE_SHARD`.
- `enzymes.glow` — свечение зачарования на ферментах.
- `editor.*` — шаг изменения значения за один клик (Shift умножает шаг на `shift-multiplier`).
- `recipe-defaults.*` — стартовые значения нового рецепта в редакторе.
- `sounds.*` — ключ звука Minecraft, громкость и высота. Если ключ неверен, звук отключается с предупреждением в консоли.

## Сообщения и lang.yml

Все сообщения, заголовки меню, названия кнопок и лор предметов лежат в `lang.yml` и используют формат **MiniMessage**:

```yaml
success: "<prefix> <green>Улучшение удалось! Вы получили <white><result></white>."
```

Недостающие ключи подхватываются из встроенного `lang.yml`, а при полном отсутствии выводится `[lang:ключ]`.

### Общие теги

| Тег | Значение |
|---|---|
| `<prefix>` | Префикс плагина из ключа `prefix` (доступен во всех сообщениях) |

### Внутренние плейсхолдеры

| Где | Плейсхолдеры |
|---|---|
| `upgrade.not-enough-coins` | `<need>` |
| `upgrade.not-enough-enzymes` | `<need>`, `<have>` |
| `upgrade.success` | `<result>`, `<chance>` |
| `upgrade.failure-lost`, `upgrade.failure-kept` | `<chance>` |
| `menu.upgrade.info-lore` | `<coins>`, `<enzymes>`, `<base-chance>`, `<extras>`, `<max-extras>`, `<bonus>`, `<chance>`, `<lose>` |
| `menu.list.title` | `<page>`, `<pages>` |
| `menu.list.recipe-lore` | `<id>`, `<result>`, `<amount>`, `<coins>`, `<enzymes>`, `<chance>`, `<bonus>`, `<lose>`, `<strict>` |
| `menu.editor.title-edit` | `<id>` |
| `menu.editor.*-lore` (числовые) | `<value>`, `<step>`, `<multiplier>` |
| `menu.editor.lose-lore`, `menu.editor.strict-lore` | `<state>` |
| `editor.saved`, `editor.deleted` | `<id>` |
| `command.enzymes-given` | `<amount>`, `<player>` |
| `command.enzymes-received` | `<amount>` |

### PlaceholderAPI

Если PlaceholderAPI установлен, в любом сообщении и лоре, адресованном игроку, можно использовать его плейсхолдеры (например `%player_name%`). Для сообщений без конкретного игрока они не обрабатываются.

### Важно про YAML

Не используйте ключи `yes`, `no`, `on`, `off`, `true`, `false` как названия разделов: YAML 1.1 превращает их в булевы значения. Поэтому «Да» и «Нет» лежат в `word.enabled` и `word.disabled`.

## Формат recipes.yml

Файл создаётся и обновляется плагином автоматически. Предметы хранятся в виде строк Base64 (нативная сериализация Paper), поэтому сохраняются все мета-данные, компоненты и зачарования.

```yaml
recipes:
  r1:
    input: <base64>
    result: <base64>
    coins: 1000.0
    enzymes: 5
    chance: 50.0
    bonus-per-extra: 10.0
    lose-on-fail: true
    strict: true
```

- ID рецептов имеют вид `r1`, `r2`, ... и присваиваются автоматически.
- Запись выполняется через временный файл и атомарную замену, чтобы файл не повредился при сбое.
- Повреждённый рецепт пропускается, остальные загружаются, ошибка выводится в консоль.
- Вручную редактировать `input` и `result` не нужно, используйте редактор.
- Параметры рецепта (`coins`, `enzymes`, `chance`, `bonus-per-extra`, `lose-on-fail`, `strict`) можно править вручную, затем выполнить `/upgrade reload`.

## Особенности и ограничения

- Работа с монетками (Vault) и меню выполняется в основном потоке, файловый ввод-вывод рецептов в отдельных виртуальных потоках.
- Для возврата в основной поток используется планировщик сущности Paper. Объявление поддержки Folia в `plugin.yml` отсутствует, плагин рассчитан на Paper.
- Результат улучшения выдаётся в инвентарь игрока, а не подставляется в слот меню.
- Дополнительные предметы расходуются по одному из каждого заполненного слота. Если в слоте лежит стак, остаток вернётся игроку при закрытии меню.
- Рецепты не связаны между собой автоматически: цепочки уровней задаются отдельными рецептами.
- Несколько рецептов с одинаковым исходным предметом разрешены, но будет применён первый подходящий по порядку ID (строгие раньше мягких).

## Решение проблем

| Проблема | Возможная причина и решение |
|---|---|
| Плагин не включается | Не установлен Vault (он обязателен). Проверьте консоль |
| «Экономика недоступна» | Нет плагина экономики, зарегистрированного в Vault |
| «Рецепты ещё загружаются» | Подождите пару секунд после старта или `/upgrade reload` |
| «Для этого предмета нет доступного улучшения» | Нет рецепта или не совпадает строгое сравнение. Проверьте предмет в редакторе или отключите строгий режим |
| В тексте видно `[lang:...]` | Ключ отсутствует в вашем `lang.yml`. Удалите файл, чтобы создать заново, или добавьте ключ |
| Меню выглядит неправильно | Проверьте раскладку слотов в `config.yml`, при ошибке в консоли будет предупреждение |
| Звук не играет | Неверный ключ звука в `config.yml`, смотрите предупреждения в консоли |
| Рецепт не загрузился | Файл `recipes.yml` повреждён. Ошибка с ID рецепта выводится в консоль |
